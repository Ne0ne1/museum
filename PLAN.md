# План: интерактивный стенд «Живая история ЧГУ»

Хакатон: музей новых технологий, экспозиция по истории ЧГУ (Чеченский государственный университет) / Чеченской Республики.
Формат: интерактивный стенд с управлением жестами руки (без прикосновения к экрану).
Команда: 2-4 человека, ~24 часа.

## 1. Идея

Посетитель подходит к стенду (ноутбук/экран + камера, направленная на зону перед экраном) и управляет контентом рукой в воздухе — как Minority Report / Iron Man интерфейс. Два режима, переключаемые одним и тем же стендом:

1. **Выбор места** — карта кампуса с точками (главный корпус, библиотека, музейный зал и т.д.). Наведение/dwell пальцем или клик — выбирает место.
2. **Таймлайн этого места** — после выбора открывается история именно выбранного места. Открытая ладонь влево → прошлое, вправо → будущее. Dwell по карточке — детали события. Кулак / кнопка «← К карте» — вернуться к выбору места.

Почему это выигрышная идея для хакатона:
- Визуально эффектно и живо смотрится на демо-стенде (жюри любит "wow"-взаимодействие).
- Не требует специального оборудования — только ноутбук с камерой.
- Технология (MediaPipe Hands) отлично документирована и стабильно работает "из коробки", что снижает риск не успеть за 24 часа.
- Легко расширяется контентом без изменения кода (JSON с событиями/точками).

## 2. Технологический стек

- **Frontend**: чистый HTML/CSS/JavaScript (без сборщика — на машине нет node/npm, а для хакатона это и не нужно). Если у кого-то из команды на ноутбуке есть Node, можно позже добавить Vite, но старт — без него.
- **Трекинг руки**: [MediaPipe Hands](https://developers.google.com/mediapipe) через CDN (`@mediapipe/hands` + `@mediapipe/camera_utils` + `@mediapipe/drawing_utils`, подключаются `<script>`-тегами с jsdelivr). Работает прямо в Chrome, определяет 21 точку кисти в реальном времени.
- **Рендер контента**: HTML/CSS с абсолютным позиционированием + `transform` для анимаций (никакого WebGL — не хватит времени полировать, а обычный DOM+CSS выглядит достаточно хорошо и надёжно).
- **Данные**: локальные JSON-файлы (`data/events.json`, `data/places.json`) — легко редактировать в течение хакатона, когда появится реальный контент.
- **Запуск на стенде**: локальный статический сервер (`python3 -m http.server` — Python есть на любой машине) или просто открыть `index.html` в Chrome (MediaPipe CDN требует интернет при первой загрузке, дальше кэшируется браузером).

## 3. Архитектура жестов

Опорные точки MediaPipe Hands (landmark indices):
- `8` — кончик указательного пальца → используется как курсор.
- `4` — кончик большого пальца → расстояние до точки 8 определяет **pinch** (щипок).
- Все 21 точки → определение "открытая ладонь" (расправлены все пальцы) для свайпа/скролла.
- Сжатый кулак (кончики пальцев близко к центру ладони) → жест смены режима.

Логика:
1. Сглаживание координат курсора (экспоненциальное скользящее среднее) — критично, иначе курсор будет дрожать.
2. Проекция координат камеры (зеркальных) в координаты экрана.
3. State machine жестов: `idle → pointing → dwelling (500мс наведение = "клик") → action`.
4. Pinch считается активным, если расстояние между точками 4 и 8 меньше порога (нормализовать на размер ладони, а не абсолютный пиксель, чтобы работало на разном расстоянии от камеры).

## 5. Тайминг на 24 часа (команда 2-4 чел.)

| Часы | Что делаем |
|---|---|
| 0–1 | Финализация идеи, распределение ролей, разбивка на файлы (уже сделано этим планом) |
| 1–4 | Базовый `handTracker.js`: видео с камеры + landmarks на экран, курсор двигается по экрану — **проверка, что трекинг вообще работает**, это самый рискованный кусок |
| 4–6 | `gestureState.js`: dwell-click, pinch, свайп ладонью, распознавание кулака |
| 6–10 | Режим "Таймлайн": лента событий, скролл жестом, раскрытие карточки по dwell-клику |
| 10–14 | Режим "Карта/Галерея": точки, hover-подсветка, pinch-zoom |
| 14–16 | Наполнение реальным контентом по истории ЧГУ (тексты, фото) — как только материалы будут готовы |
| 16–18 | Полировка UI/анимаций, титульный экран, лого музея/ЧГУ, звуковые эффекты (опционально) |
| 18–20 | Тестирование на реальном освещении месте демо, калибровка порогов жестов |
| 20–22 | Запасной "fallback" режим управления мышью/тапом (на случай если камера/свет подведут во время презентации) |
| 22–24 | Репетиция питча, финальный прогон, багфиксы |

Роли (при команде 3-4 человека):
- **Trekking/gestures dev** — `handTracker.js`, `gestureState.js`.
- **Frontend/UI dev** — `timeline.js`, `gallery.js`, CSS/анимации.
- **Контент/дизайн** — сбор материалов по истории ЧГУ, тексты, фото, структура `events.json`/`places.json`.
- **Питч/демо** — готовит сценарий показа жюри, запасной план Б, следит за таймингом.

Если команда из 2 человек — объединить роли (1: трекинг+гестуры, 2: UI+контент), питч готовят вместе в последние часы.

## 6. Риски и Fallback-планы

- **Плохое освещение зала на демо** → MediaPipe Hands чувствителен к освещению. Fallback: держать поблизости настольную лампу/подсветку, заранее протестировать на месте (пункт 18–20 в тайминге).
- **Трекинг "дёргается"/шумит** → сглаживание координат (EMA), увеличить dwell-time для клика.
- **Жюри не понимает, что происходит** → обязательно добавить на экран подсказки-иконки жестов ("покажи открытую ладонь и двигай — листаешь", "сведи пальцы — увеличиваешь") в первые секунды взаимодействия.
- **Не успели с жестами** → всегда должен работать fallback через мышь/клик, чтобы демо не сломалось на сцене.
- **Нет контента к дедлайну** → плейсхолдеры (`data/*.json`) с заглушками фото уже готовы, легко заменить в последний момент.

## 7. Питч для жюри (черновая структура)

1. Проблема: в музеях новых технологий скучно/неинтерактивно смотреть на стенды с текстом за стеклом.
2. Решение: стенд без единого прикосновения — жестовое управление рукой, погружение в историю ЧГУ и республики.
3. Демо живьём: показать оба режима на сцене (таймлайн → карта/галерея).
4. Технология: MediaPipe Hands, работает на обычной веб-камере, дешёвое воспроизведение в любом музее без спец-оборудования.
5. Масштабируемость: легко подключить любой другой контент музея через JSON — не только про ЧГУ.
